결제 영역 서비스 카탈로그
기준일: 2026-09-30
이 문서는 결제 영역 서비스가 어떤 서비스와 구성요소에 기대어 동작하는지 적는다. 새 기능을 설계하거나 배포 영향 범위를 볼 때 먼저 확인한다.
pay-gateway(결제 게이트웨이): 앱, 웹, 가맹점 서버에서 들어오는 결제 요청을 받는 입구다. 요청이 오면 auth-token(인증 토큰 서비스)으로 사용자를 확인하고, risk-engine(이상거래 탐지 엔진)의 판정을 받은 뒤 pg-connector(PG 연동 모듈)에 승인을 요청한다. 승인 결과는 ledger-db(원장 DB)에 기록하고 kafka-main(메인 메시지 브로커)에 결제 완료 이벤트로 낸다.
pg-connector: 외부 PG사인 한빛PG와 다온PG에 승인, 취소, 결과 확인 전문을 보낸다. 국내 카드는 두 곳에 나눠 보내고 해외 카드는 다온PG로만 보낸다.
auth-token: 로그인 세션과 결제용 일회성 토큰을 발급한다. 세션 정보는 redis-session(세션 캐시)에 저장한다.
merchant-api(가맹점 API): 가맹점 서버가 주문 결제, 환불, 거래 확인을 요청하는 창구다. 바깥 요청은 api-edge(외부 API 관문)를 거쳐 들어오고, 실제 결제 처리는 pay-gateway에 넘긴다.
risk-engine: kafka-main에서 결제 이벤트를 읽어 이상 패턴을 학습하고, 결제 시점에는 pay-gateway의 판정 요청에 실시간으로 답한다.
