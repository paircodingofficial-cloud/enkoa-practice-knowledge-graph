# KG 자동화 파이프라인 실습 가이드

문서를 지식 그래프로 만들고, 원문과 정답 목록으로 품질을 확인합니다.
부록에서는 Wikidata 후보를 LLM이 선택해 기존 노드에 외부 ID를 저장합니다.

## 교안별 진행 순서

| 자료 | 사용하는 데이터 | 진행 내용 |
|---|---|---|
| 교안 01 일반 실습 | pandas 2.0.3 변경 문서 | 스키마와 청크 준비 -> 그래프 생성 -> 평가용 결과 저장 -> 중복 노드 통합 |
| 교안 01 함께 따라하기 | 의료 논문 원문 4문장 | 약물과 질환의 치료 사용 관계에 같은 절차 적용 |
| 교안 02 본문 | pandas 저장본과 골드 | 저장 관계 검사 -> 골드 비교 -> 청크 설정 변경 -> 전후 비교 |
| 교안 02 핵심 코드 이어서 보기 | 의료 논문 저장본과 골드 | 본문에서 배운 검증과 재실행을 의료 논문에 적용 |
| 부록 | LangChain 개체와 Wikidata 후보 | 후보 검색 -> LLM 선택 -> 후보 ID 검사 -> Neo4j 저장 |

- 교안 01의 함께 따라하기는 강사와 코드를 작성합니다.
- 교안 02와 부록에는 함께 따라하기나 빈 작성 영역이 없습니다.
- 마지막 **핵심 코드 이어서 보기**는 학생용에도 완성 코드를 넣었습니다. 새 커널에서 해당 절의 첫 코드부터 실행할 수 있습니다.
- 정답과 해설은 수업이 끝난 뒤 강사가 공유합니다.

## 실행 준비

패키지 설정은 저장소 최상위의 `pyproject.toml`과 `uv.lock`에 있습니다.
저장소 최상위 폴더에서 실행하세요.

```bash
uv sync
```

노트북 커널은 **저장소 최상위 `.venv`의 Python**을 선택합니다.
Neo4j와 서버 버전에 맞는 APOC Core 플러그인을 준비하고 DB를 시작하세요.
부록의 동적 라벨 문법은 Neo4j 5.26 이상을 사용합니다.

`.env.example`을 참고해 교안 폴더 또는 상위 폴더에 `.env`를 준비합니다.
코드는 현재 작업 폴더부터 상위로 찾아 가장 가까운 `.env` 한 파일을 읽습니다.
아래 포트는 Neo4j 기본 Bolt 포트 `7687`이며, 다른 포트로 띄운 DB를 쓰면 그 포트로 바꿉니다.

```dotenv
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=실제_비밀번호
OPENAI_API_KEY=실제_API_키
```

- **LLM:** `gpt-5.6-luna`
- **임베딩:** `text-embedding-3-large`, 768차원
- **부록:** Wikidata 검색은 공개 API이며, LLM 후보 선택에는 OpenAI API 키가 필요합니다.

DB 연결 오류는 서버와 포트, 인증 오류는 계정과 비밀번호를 확인합니다.
모델 접근 오류는 API 계정과 모델 사용 권한을 확인합니다. 모델 호출에는 API 사용 비용이 발생합니다.
설치 버전은 `uv.lock`에 맞추고, 노트북의 `await` 코드는 Jupyter 셀에서 그대로 실행합니다.

## 입력과 결과 파일

**원문은 추출 입력, 저장본은 실행 결과, 골드는 원문을 읽고 작성한 정답 목록입니다.**
파일명의 `demo`는 pandas, `followalong`은 의료 논문, `assignment`는 과제의 의약품 자료입니다.

| 파일 | 내용과 사용 위치 |
|---|---|
| `data/demo_document.json` | pandas 2.0.3의 수정 항목 4개와 출처 |
| `data/followalong_document.json` | 의료 논문 원문 4문장과 출처 |
| `data/demo_gold.json` | pandas 정답 5관계 |
| `data/followalong_gold.json` | 의료 논문 정답 3관계 |
| `output/baseline_demo.json` | 교안 01 일반 실습에서 저장하고 교안 02 본문에서 읽는 기준 결과 |
| `output/baseline_followalong.json` | 교안 01 함께 따라하기에서 저장하고 교안 02 핵심 코드에서 읽는 기준 결과 |
| `output/large_demo.json` | 교안 02 본문에서 청크 설정을 바꿔 실행한 pandas 결과 |
| `output/large_followalong.json` | 교안 02 핵심 코드에서 청크 설정을 바꿔 실행한 의료 논문 결과 |
| `data/assignment_document.json`, `data/assignment_gold.json` | 의약품 설명서 5개 절과 이상반응 정답 5관계 |
| `output/baseline_assignment.json` | 과제 LV1에서 저장하고 LV2에서 읽는 기준 결과 |
| `output/large_assignment.json` | 과제 LV2에서 청크 크기를 바꿔 실행한 결과 |

먼저 교안 01을 실행해 두 `baseline` 파일을 만드세요.
각 저장본에는 원문, 추출 관계, 청크, 모델, 스키마, 프롬프트와 실행 ID가 들어 있습니다.
재실행 결과는 새 실행 ID로 조회하고 `large` 파일에 저장해 기준 결과와 구분합니다.

## 청크 설정과 평가 기준

분할에는 `RecursiveCharacterTextSplitter`를 사용합니다.
`LangChainTextSplitterAdapter`는 분할 결과를 Neo4j 빌더의 청크 형식으로 바꿉니다.

| 구분 | 기준 크기 / 겹침 | 변경 크기 / 겹침 |
|---|---|---|
| 교안 | 500 / 100자 | 2000 / 400자 |
| 과제 | 300 / 80자 | 1000 / 80자 |

교안은 겹침 비율을 20%로 유지하고, 과제는 겹침을 80자로 고정합니다.
실제 겹침은 문단 경계에 따라 달라지며 큰 청크가 항상 더 정확한 것은 아닙니다.

- **평가 대상:** 스키마에 맞춰 가지치기한 뒤, 중복 노드를 합치기 전에 저장한 관계입니다.
- **스키마 준수율과 근거 원문 일치율:** 같은 저장 관계 전체를 분모로 각각 계산합니다.
- **정밀도, 재현율, F1:** 고유한 `(주어, 관계, 목적어)`를 같은 골드와 비교합니다.
- **오류 확인:** FP는 잘못 뽑은 관계, FN은 놓친 관계입니다. 원문과 함께 읽습니다.

중복 노드 통합은 현재 실행에서 라벨과 이름이 같은 노드에 적용합니다.
관계가 합쳐지면 일부 근거가 사라질 수 있어 평가용 결과를 먼저 JSON에 보관합니다.

## 과제 진행

1. **LV1:** 의약품 원문과 스키마 준비 -> 그래프 생성 -> 평가 자료 저장 -> 노드 통합.
2. **LV2:** LV1 결과 읽기 -> 스키마와 근거 검사 -> 골드 비교 -> 청크 크기 변경 -> 전후 비교.

과제는 `Drug -> HAS_SIDE_EFFECT -> Symptom` 관계를 다룹니다.
검사는 원문 보존, 평가 범위와 계산 기준을 확인하며, LLM이 특정 점수를 내도록 요구하지 않습니다.
원문의 출처와 선정 기준은 [데이터 설명](data/README.md)을 참고하세요.

## 부록: LLM으로 외부 KB 후보를 선택해 저장하기

[부록 노트북](부록_외부_KB의_표준_ID에_개체_연결하기.ipynb)

1. **후보 조회:** `kb_lookup.py`로 이름과 별칭을 검색하고 후보의 종류, 설명과 공식 사이트를 읽습니다.
2. **LLM 판단:** `ChatPromptTemplate`에 내 개체와 후보 목록을 넣습니다. 구조화된 출력으로 상태, Q-ID와 이유를 받습니다.
3. **저장 전 검사:** 선택한 ID가 실제 후보에 있는지, 보류 상태라면 ID가 `None`인지 확인합니다.
4. **Neo4j 저장:** 내부 `standard_id`를 유지하면서 외부 ID와 이유를 추가합니다. 보류이면 외부 ID 없이 사유를 저장합니다.
5. **외부 정보 활용:** DB에 저장한 Q-ID로 Wikidata의 설명과 공식 사이트를 조회해 `kb_` 속성에 추가하고 원본 항목 링크를 만듭니다.
6. **SPARQL 관계 조회:** 같은 의존 라이브러리를 공유하는 다른 소프트웨어를 Wikidata에서 찾습니다. 결과는 표로 확인하며 LLM은 다시 호출하지 않습니다.

후보 조회 함수는 정보를 가져오고, LLM은 후보를 선택하며, 저장 함수는 검사한 결과를 기록합니다.
